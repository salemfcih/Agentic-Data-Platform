# 04 — Layer-by-Layer Component Audit, Challenge & 2026 Market Benchmark

This document records the Chief Architect teardown of the baseline open-source lakehouse architecture and justifies every upgrade incorporated into **AegisLake**.

| Layer | Baseline Component | Core Responsibility | Key Pros | Key Cons / 2026 Risks | 2026 Market Alternatives | AegisLake Target Decision |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Ingestion (Files/DB)** | Apache NiFi | Flow-based file/DB routing & provenance | Visual flows, backpressure, strong provenance | Weak as a heavy transformation engine; lacks native event replay log | Debezium + Kafka Connect, Informatica IDMC, Airbyte | **Keep NiFi for edge/file routing**; use **Debezium/Kafka Connect** for DB CDC & **IDMC** for enterprise B2B/MFT |
| **Ingestion (APIs/SaaS)** | n8n | Low-code API & webhook workflows | Fast prototyping for SaaS webhooks | **Not an analytical ELT engine**; memory bottlenecks, weak schema contracts, no CDC checkpoints | **dlt**, Airbyte, Fivetran, Confluent HTTP Source | **Replace for bulk ELT with `dlt` / Airbyte**; retain n8n solely for lightweight operational action triggers |
| **Event Backbone** | *(Missing in baseline)* | Durable decoupled streaming bus | N/A | Direct Ingestion -> Flink coupling causes brittle failure recovery & no replay | **Apache Kafka / Confluent**, Redpanda, Apache Pulsar, Google Pub/Sub | **Introduce Kafka + Schema Registry + AsyncAPI** as the mandatory event backbone |
| **Metadata Catalog** | DataHub | Active metadata, lineage, business glossary | Rich graph model, active actions, strong lineage | Moderate ops footprint (Kafka/ES/MySQL) | **OpenMetadata**, Atlan, Collibra, Dataplex | **Keep DataHub** (wired to OpenLineage & AsyncAPI Catalog-as-Code) |
| **Data Quality** | Great Expectations | Python-based declarative data assertions | Mature ecosystem, rich expectation library | Full-table scan cost; misses unknown distributional anomalies; no contract governance | **Soda v4 (ODCS)**, dbt Tests + Elementary, Monte Carlo | **Upgrade to Soda v4 + ODCS Contracts** + Iceberg metadata checks + Evidently anomaly detection |
| **Access Control** | Apache Ranger + Generic Auth | Fine-grained RBAC/ABAC masking & row filtering | Proven enterprise Hadoop/Trino/Spark security | Generic `Auth` undefined; split-brain risk with Polaris RBAC; no AI/MCP policy engine | **OPA**, Apache Gravitino pushdown, Immuta, Ping Identity / Keycloak, SPIFFE | **Keep Ranger** orchestrated via **Gravitino**, add **OIDC + SPIFFE/SPIRE** & **OPA** for API/MCP/Agent authz |
| **Object Storage** | MinIO (OSS CE) | S3-compatible data lake object store | Historically simple on-prem S3 | **CRITICAL 2026 RISK**: MinIO CE archived, admin UI stripped, unpatched CVEs, anonymous pulls removed | **Apache Ozone**, **Ceph RGW**, SeaweedFS, MinIO AIStor (commercial), Cloud S3/GCS | **Replace MinIO CE** with **Apache Ozone** (Cloudera-aligned) or **Ceph RGW** on-prem; GCS/S3 in cloud |
| **Table Format & Catalog** | Apache Iceberg + Polaris | Open ACID tables + Iceberg REST catalog | Vendor-neutral standard; Polaris ASF TLP with credential vending | Polaris scope is Iceberg-only (doesn't govern Kafka, filesets, or ML models) | Delta UniForm, Hudi, **Apache Gravitino**, Unity Catalog OSS | **Keep Iceberg v3 + Polaris**; layer **Apache Gravitino** above as federated metalake |
| **Data Versioning** | LakeFS | Git-like branching on object storage | Atomic commits across multimodal files | Commercial feature for Iceberg; conflicts with native Iceberg branching (`Refs`) | **Iceberg Native WAP**, Project Nessie, DVC | **Scope LakeFS to unstructured AI corpora**; use **Iceberg Native WAP** for tabular CI/CD |
| **Batch & Stream Compute** | Spark + Flink (+ NiFi) | Distributed ETL & stateful stream processing | Industry-standard open compute triad | Missing SQL modular transform layer (`dbt/SQLMesh`) & AI compute (`Ray`); Airflow shouldn't cron Flink | **SQLMesh / dbt**, **Ray Data**, DuckDB, RisingWave | **Keep Spark + Flink** (via Flink K8s Operator); add **SQLMesh/dbt** & **Ray**; remove NiFi from Processing |
| **Serving & Semantics** | Trino *(No Semantic Layer)* | Distributed federated SQL serving | Best-in-class federation & Iceberg support | Not built for 5k+ QPS sub-50ms lookups; **no Semantic Layer** causes KPI drift & LLM hallucinations | **StarRocks / Doris**, ClickHouse, **Cube / dbt MetricFlow**, Looker | **Keep Trino**; pair with **StarRocks** (high-QPS OLAP) + mandatory **Semantic Layer (Cube / MetricFlow)** |
| **Orchestration** | Apache Airflow | Pipeline scheduling & dependency DAGs | Huge ecosystem; Airflow 3.0 adds asset awareness | Poor fit for durable, stateful multi-agent loops and long-running human-in-the-loop waits | **Dagster**, Prefect, Kestra, **Temporal** | **Upgrade to Airflow 3.x** (data assets) + pair with **Temporal** (durable agent workflows) |
| **ML / AI & Inference** | Feast + MLflow + ONNX/TF Serving | Feature store, model registry, classical serving | Clean MLOps separation | **Zero GenAI / Agentic support** (no LLM gateway, vector DB, RAG, MCP gateway, guardrails) | **KServe + vLLM / Triton**, Hopsworks, LangGraph, Qdrant | **Keep Feast + MLflow 3.x**; upgrade serving to **KServe (vLLM + Triton)** + full 7-layer GenAI & MCP plane |
| **Model & Platform Monitoring** | WhyLabs + Prometheus/Grafana | Drift profiling & infra metrics | Lightweight metrics collection | **CRITICAL 2026 RISK**: WhyLabs discontinued commercial operations in 2026; metrics lack traces/lineage | **Langfuse**, **Evidently AI**, Arize Phoenix, **OpenTelemetry + Grafana LGTM** | **Replace WhyLabs** with **Evidently AI + Langfuse**; evolve Prometheus to **OTel + Grafana LGTM + OpenLineage** |
